### 1.2 G506 权威实测（复盘引擎 /api/review/sku/G506 实跑，供口径校验）

- G506（Redmi Note 14 4G 钢化膜，常规开发，评级 XC，成本价 ¥12.0266）：段级卡点 签样(2025-11-11)→采购(2026-04-30) **实际 170 天 vs 目标 1 天，超 169 天**；寄送→拍摄交付 184 天 vs 10（同一停滞期）。
- **考核口径（2026-09-21 用户纠偏后定稿）**：考核时钟起点 = **取数**（提案→取数 仅挂「提案超期」异常，不计入考核）。按路线总评级（seg_rules.ROUTE_TARGETS）：
  - ⚠️ **2026-10-19 口径变更**：该段目标由 75 天收紧为 **1 天**；锚点改为 Part1「提案日期」（业务真实提案日），老单据未填则回退「创建时间」。
  - 运营路线 取数(2025-10-30)→max(上架,广告)(2026-05-15) = **197 天**，超 60 天底线 **137 天**，评级差；
  - 空运路线 取数→最晚空运到货(2026-06-19) = **232 天**，超 60 天底线 **172 天**，评级差；
  - 海运路线 取数→最晚海运到货(2026-06-28) = **241 天**，超 69 天评级线 172 天，评级差（海运不设底线）。
  - **G506 统一结论：晚 137~172 天**（此前"海运 145/空运 125 → 晚 96~116 天"为错误口径，已废弃）。
- **损益推算定稿口径（2026-09-22 用户确认）**：推迟天数**统一取空运路线超底线天数**——空运到货即可开始销售，空运晚的天数就是全部损失窗口。销量损失区间 = 推迟天数 × 日均销量区间（XC = 1.38~5.5，商品资料表 A1 口径）；亏损 = 销量损失区间 × 单价。G506 定稿结果：**172×1.38 ~ 172×5.5 = 少卖 237~946 件**，按成本价 ¥12.0266 计亏损 **¥2,855 ~ ¥11,377**（商品资料表内无膜售价列，暂按参考成本价；补售价后按售价重算）。
- **核心原因定位要求（2026-09-22 用户确认）**：推迟/提前的核心原因必须定位到**依赖链**——例如 G506 实为第一轮取数（2025-10-30）完成后长期无人提交后续提案、开发整体搁置，直到 2026-04-30 才重新提案。异常定位不能只列最差段，要给出因果链（上一节点完成后下游长期未启动 → 指向漏报/搁置环节）并标注人工漏报嫌疑。
- ⚠️ 数据坑：G506 有两轮 Part1（2025-10-30 与 2026-04-30），复盘引擎把新一轮提案配旧一轮取数，出现"提案→取数 = -182 天"反向段。**多轮提交的去重/合并是 P0 数据问题。**

## 2. 产品定义

### Product Goals

1. **状态可见**：每日自动产出在研 SKU 的全节点状态与目标达成情况，无需人工跑数。
2. **异常可定位**：任一 SKU 异常时，30 秒内定位到具体段级/部门/责任人，并可导出带甘特图的核查报告。
3. **损失可量化**：对已完成流程，按评级推算销量影响，用金额（推迟天数×日均销量×单价）支撑复盘与上报决策。

### User Stories

1. As a 流程管理员, I want SKU 列表默认从新到久排序, so that 我每天打开页面第一眼看到最新的在研 SKU。
2. As a 流程管理员, I want 每天 09:00/14:30 钉钉数据同步后自动 ETL 入库并生成流程复盘报告, so that 我不用手工触发导入再手工拼报告。
3. As a 流程管理员, I want 在研 SKU 出现"即将超期"时收到人工干预提醒, so that 我能在异常发生前介入。
4. As a 流程管理员, I want 对已异常 SKU 一键导出带甘特图的 Excel 报告（末尾含"人工核对"列）, so that 我可以线下核查异常原因并回填结论。
5. As a 运营负责人, I want 异常售前 SKU 自动上报, so that 相关方能及时获知超期情况。
6. As a 管理层, I want 看到已完成流程的销量/毛利影响推算（增益+损益）, so that 我能评估流程时效对生意的影响。
