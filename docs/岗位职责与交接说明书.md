# 岗位职责与交接说明书

> **适用对象**：部门管理者、岗位带教人、交接双方  
> **用途**：人员入职定责、离职交接、跨岗备份、招聘需求定义  
> **版本**：v1.0 ・ 2026-09-18  
> **内部资料**：含人员分工信息，请勿外传

---

## 一、这份文档解决什么问题

人员流动是这个流程最大的隐性风险。本系统的审批数据里已经留下了痕迹：**截至 2026-09-18，  
审批记录中标注「已离职」的人员共有 7 位**，其中有人在关键环节承担了大量工作。

本手册做三件事：

1. 把**岗位**与**流程环节**对齐，让每个环节都有明确的责任人（而非"以前是谁在做"）；
2. 用系统数据指出**当前的交接断层与单点风险**；
3. 提供**可复用的交接检查表**，让每次人员变动都按同一套动作走，不漏项。

## 三、各岗位职责明细

### 3.1 产品开发岗

- **职责**：对新机型号做立项判断，拿到真机数据并补齐产品信息，完成样机测试与寄拍。
- **涉及动作**：`提案确认`、`取得手机数据`、`产品信息补充`、`通知_手机数据已取得`、`全套样品测试完成`、`寄送拍摄团队`
- **关键交付**：产品信息（供全流程使用）、样机（供测试与拍摄）
- **在系统里看**：「明细查询 → Part1」按创建人筛选
- **能力要求**：选品判断力、跨部门沟通（要推动供应商/拍摄团队）、对时效敏感
- **⚠️ 当前状态**：该岗位主线工作**高度集中在单一人员身上**，且此人同时承担 Part2 样品测试、  
  Part6 寄拍、Part8 上架确认 —— **本流程最大的单点风险**。建议尽快指定备份人并做影子跟单。

### 3.2 需求与采购岗

- **职责**：汇总各站点备货需求与特殊需求数量，完成采购下单。
- **涉及动作**：`站点需求收集`、`特殊需求数量收集`、`采购下单`
- **关键交付**：准确的**分站点备货数量**（决定后续往哪些仓发货，错了全链条返工）
- **在系统里看**：「明细查询 → Part2」，重点核对「东南亚印尼/泰国/菲律宾、亚马逊各站点…」等列
- **能力要求**：细心（21 个站点字段逐个填）、与运营/供应商的双向对接
- **⚠️ 当前状态**：`特殊需求数量收集` 原执行人已离职；`站点需求收集` 有在职人员承接，但**无备份**。

### 3.3 签样/仓储岗 ★全流程闸门

- **职责**：新品抵达本地仓后完成到货检查与签样。
- **涉及动作**：`本地仓到货检查`
- **关键交付**：**签样完成** —— 这是全流程的闸门，未完成则采购下单无法推进
- **在系统里看**：「明细查询 → Part3」（产品部达成率现按 Part6 素材交付口径统计，见 3.5 素材岗）
- **能力要求**：实物检验、与供应商的退换沟通
- **⚠️ 当前状态**：**该动作原执行人（谢雪娜）已离职，且承担过 249 次到货检查 ——  
  这是当前交接最紧急的缺口**。全流程闸门由此人把控，必须优先补位。

### 3.4 发货执行岗

- **职责**：本地仓向 15 个渠道仓发货，逐货件号建单。
- **涉及动作**：`发货`
- **关键交付**：货件号、发货数量、发往渠道仓库（三者错一个，Part8 到货就匹配不上）
- **在系统里看**：「货件运输」页（逐票判定 + 渠道聚合）、「明细查询 → Part5」
- **能力要求**：批量操作的准确性、熟悉各渠道仓的发货规则
- **⚠️ 当前状态**：单据量极大（单批次 3608 次发货动作），**几乎由单一人员承担，无备份**。  
  一旦请假或变动，Part5 会直接停摆。

### 3.5 素材岗 ★产品部终节点

- **职责**：接收拍摄团队交付的素材，加工成可上架的营销素材并通知完成。
- **涉及动作**：`素材接收`、`产品营销素材加工`、`新品营销素材完成通知`
- **关键交付**：最终素材文件 + `最终素材上传路径`、`橱窗图与视频上传路径`
- **终节点**：**素材交付** = Part6 `产品营销素材加工` 的完成时间（=Part6「产品营销素材加工」，审批记录 audit 时间；该节点无系统业务时间列）= 产品部考核终点
- **在系统里看**：「明细查询 → Part6」
- **能力要求**：素材规范理解（各站点尺寸/风格差异）、与拍摄团队的进度对接
- **⚠️ 关键提醒**：素材**不必等 Part5 发货**就能启动（签样完成即可寄拍）。  
  这条认知如果不交接清楚，新人会重蹈"页面 coming soon"的覆辙。

### 3.6 运营上架岗

- **职责**：各站点首次上架（占位）→ 素材齐备后最终上架 → 渠道仓到货后手机上架确认。
- **涉及动作**：`新品首次上架`、`新品上架完成`、`上架`、`手机上架确认`
- **关键交付**：各区域上架完成图片、最终上架完成时间、手机上架日期
- **在系统里看**：「明细查询 → Part4/Part7/Part8」；「路线达标」页看运营路线评级
- **能力要求**：多站点后台操作（亚马逊各国后台差异不小）、对 listing 规范熟悉
- **⚠️ 当前状态**：首次上架与最终上架由不同人分担，属合理设计；但**上架确认环节多人共担，  
  责任边界模糊**，建议明确"哪个站点归谁"。

### 3.7 广告投放岗 ★运营部终节点

- **职责**：最终上架后完成广告设置（终节点的一环）。
- **涉及动作**：`广告设置`
- **关键交付**：广告上架完成时间、`是否完成广告上架`
- **在系统里看**：「明细查询 → Part7」；Part8 的 `检查广告是否设置完成` 是复核
- **能力要求**：广告后台操作、投放预算与节奏把控
- **⚠️ 当前状态**：由单一人员承担，且与运营上架岗共同构成运营部终节点 ——  
  **两个岗位任缺一个，运营部终节点就无法达成**。

### 3.8 仓储收货岗 ★后勤部终节点

- **职责**：渠道仓到货确认并通知。
- **涉及动作**：`到货通知`
- **关键交付**：渠道仓到货时间、到货渠道仓、货件号匹配
- **在系统里看**：「货件运输」页（超时票判定）；「明细查询 → Part8」
- **能力要求**：与货代/渠道仓的对接、异常到货（短少/破损）处理
- **⚠️ 当前状态**：该动作由单一人员承担**3226 次**，是单据量最集中的岗位，**无备份**。

### 3.9 运营推广岗

- **职责**：到货后 1 天内完成手机上架确认，2 天内启动促销与邀评。
- **涉及动作**：`新品促销开始`、`新品邀评开始`
- **关键交付**：促销/邀评启动记录
- **在系统里看**：「明细查询 → Part8」
- **能力要求**：对平台流量窗口的敏感度（**这是全流程时效最紧的两个动作**）
- **⚠️ 当前状态**：促销原执行人之一已离职（刘芸蕾，124 次），当前由在职人员承接。

### 3.10 运营协调岗

- **职责**：产品立项后通知东南亚运营，本地仓到货后通知跨境店负责人。
- **涉及动作**：`通知_东南亚运营`、`通知跨境店负责人`、`通知_产品立项`
- **关键交付**：跨部门信息同步（属并发通知，不单独计时，但**漏通知会造成下游空转**）
- **在系统里看**：各环节审批记录中的通知节点
- **能力要求**：跨部门关系维护、信息传递的及时性

### 3.11 多部门会签

- **职责**：上架确认、广告检查等节点由多部门联合确认。
- **典型组合**：上架确认与广告检查常由 3~5 人联合签署（如"梁子锋,黄顺良,杨晓源,张德怡,黄景阳"）。
- **在系统里看**：审批记录中出现的多人会签节点
- **⚠️ 注意**：会签人员组合不稳定（历史数据里出现过 10 余种组合，含已离职人员），  
  建议固定会签名单，避免"以为别人签了"的漏签。

## 五、岗位交接检查表（每次人员变动都走一遍）

### 5.1 交接前（原岗位人准备）

- [ ] 列出在办 SKU 清单：打开「明细查询」，按自己为创建人/执行人筛选**未闭环**单据
- [ ] 标注每个 SKU 的当前卡点环节与下一步动作
- [ ] 整理未完成的外部对接（供应商、拍摄团队、货代、渠道仓联系人）
- [ ] 移交账号与权限（钉钉审批权限、各平台后台账号、共享文件夹）
- [ ] 移交非系统内的隐性知识：常见返工原因、各站点特殊要求、供应商脾气
- [ ] 更新本手册第三节中"当前执行人"栏位

### 5.2 交接中（双方共同确认）

- [ ] 逐条过一遍在办 SKU，说明状态与后续动作
- [ ] 带新人**实操一遍**最常做的动作（如 Part2 备货数量填写、Part5 建货件单）
- [ ] 讲清**本岗位涉及的终节点**（如 Part3 签样 = 全流程闸门；Part6 产品营销素材加工 = 产品部终节点）
- [ ] 讲清时效红线（本岗位对应的天数要求）
- [ ] 说明审批被打回的常见原因及处理方式

### 5.3 交接后（管理者验收）

- [ ] 新人独立完成 ≥3 个 SKU 的完整流转
- [ ] 一个月后在系统中验证：新人的执行记录已出现在对应环节
- [ ] 抽查 1 个新人经手的 SKU，核对时效是否达标、字段是否填全
- [ ] 确认备份人名单已更新，且备份人能独立操作

## 六、招聘需求参考

当岗位需要补充人力时，可直接引用下表作为 JD 依据：

| 岗位     | 核心要求         | 面试可考察的点                      |
| ------ | ------------ | ---------------------------- |
| 签样/仓储岗 | 实物检验经验、供应商沟通 | 遇到过货不对版怎么处理；如何保证签样不积压        |
| 发货执行岗  | 批量操作准确性、货代对接 | 如何避免货件号填错；多仓并发发货怎么排优先级       |
| 运营上架岗  | 亚马逊多站点后台操作   | 各国 listing 规范差异；首次上架与最终上架的区别 |
| 素材岗    | 素材规范、跨团队协作   | 各站点素材尺寸差异；如何催拍摄团队按期交付        |
| 产品开发岗  | 选品判断、跨部门推动   | 如何判断一个型号值得开发；提前开发与常规开发的区别    |

## 七、附：常见认知误区（新人必读）

| 误区            | 事实                                       |
| ------------- | ---------------------------------------- |
| "素材要等货发出去才能拍" | ❌ 签样完成即可寄拍，素材与发货解耦。这是"页面 coming soon"的根因 |
| "首次上架 = 最终上架" | ❌ Part4 是占位防抢 listing，Part7 才是素材齐备后的正式上架 |
| "审批单提交了就算完成"  | ❌ 系统按**关键动作**计时，提交申请只是开始                 |
| "Part9 检查是形式" | ❌ 它是不合格的 SKU 被发现并回流修正的唯一入口               |
| "超时几天没关系"     | ❌ 到货后促销必须 2 天内启动，超时直接错过流量窗口              |
