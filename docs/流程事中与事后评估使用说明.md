# 流程事中与事后评估 使用说明

> 面向：流程管理员 / 日常催办人。
> **事中页回答「现在卡在哪、该催谁」；事后页回答「已经发生了什么、亏了多少」。**
> 两页是同一份数据（钉钉审批导出 → ETL 入库）的两个视角，不是两套数。

---

## 一、两个页面在哪、什么时候用

| 页面 | 侧栏入口 | 回答的问题 | 数据更新节奏 |
| --- | --- | --- | --- |
| 事中日报 | 事中日报 | 现在哪个 SKU 卡在哪一段、卡了多久、该找谁 | 每天 **09:20 / 14:50** 自动管线跑完即可看 |
| 事后评估 | 事后评估 | 已闭环 SKU 的时效 / 销量 / 金额三指标 | 每次打开**实时计算** |

配套的两条自动化链路（无需人工触发）：

1. **上游同步**：计划任务 `DingTalkApprovalSync` 每天 09:00 / 14:30 拉钉钉审批导出（约 7.5 分钟）。
2. **下游管线**：计划任务 `DataAdmin-AutoPipeline` 每天 09:20 / 14:50 增量导入 → 复盘重算 → KPI 快照 → 生成当日日报。

> ⚠️ 下游必须晚于上游跑完。若改动钉钉同步时间，**必须同步改** `scripts/install_auto_etl.ps1` 并重新注册，否则管线会读到「写了一半」的 xlsx。

## 二、事中日报页怎么读

### 2.1 顶部四个 KPI

| 指标 | 含义 |
| --- | --- |
| 在研 SKU | 任一 Part 仍处于「审批中」的 SKU 数 |
| 超期 SKU | **当前停留环节**已超过该段目标天的 SKU 数（2026-10-19 口径；历史段超期不丢，仍在总表「超期段」列与超期明细里） |
| 临近预警 | 已用 ≥ **目标 × 85%** 目标天、且未超期的**环节数**（不是 SKU 数）。可与「超期」并存：一个 SKU 当前段超期、另一段刚到预警线，两边都会出现 |
| 多轮提交 | 同一 Part 单据被撤回重提的 SKU 数 |

### 2.2 段状态机（唯一判据，别凭感觉）

对每一段（起点节点 → 终点节点）判定：

| 状态 | 判据 | 处理 |
| --- | --- | --- |
| 未开始 | 起点节点无时间 | 等前序，不用管 |
| 进行中 | `已进行 ≤ 目标 × 85%` | 正常推进 |
| 预警 | `已进行 > 目标 × 85%` 且 `≤ 目标` | **提前干预**，此时还来得及 |
| 超期 | `已进行 > 目标` | 需要上报 / 跟进 |
| 已完成 | 终点节点已有时间 | 不进预警区（不误报已完成段） |
| 留空 | 该段是部门间留空段 | 不计考核 |

- `已进行 = 今天 − 起点时间`；`超期天数 = 已进行 − 目标天`（只对超期段有值）。
- **判据是 `>` 不是 `≥`**：刚好等于目标天仍算预警，不算超期。
- 85% 系数可在 **时效规则配置 → 事中预警系数** 调整（默认 0.85）。

### 2.3 页面上的表

1. **风险预警区**：`当日新超期`（今天刚越过目标线 → **今天就要上报**）、`持续超期`（此前已超期 → 跟进）。
2. **临近超期预警**：达到目标天 85% 的段 → 这是事中干预价值最高的一栏。
3. **在研清单**：每个在研 SKU 一行（SKU / 机型 / 当前停留环节 / 部门 / **已停留** / 距超时 / 预警段 / 状态 / 运输 / 多轮 / 负责人）。
   - **已停留**（2026-11-06 新增）：该段起点到今天的天数，**任何段都有值**。运输在途 / 渠道未发货
     没有目标天，这一列是它们唯一的时钟 —— 之前这 16 个 SKU 在页面上完全看不出停了多久
     （G597 在途 28 天、G599 emag 未发货 22 天，页面一片平静）。
   - **距超时** = `目标 − 已停留`；该段没设目标天时显示灰字「无目标」，**不参与超期与预警判定**。
   - **运输**：只给计数徽标（「未到货 N 国」/「未发货 N 渠道」），鼠标悬停才展开名单。
4. **无目标段**：当前停留段没设目标天的 SKU 单列一块，口径 = 日报 xlsx「风险预警」sheet 的
   「⚠ 无目标段」小节。这批 SKU 永远不会出现在「超期 / 预警」两个列表里，只能按「已停留」
   人工判断要不要催 —— **别把它当「没问题」**。
5. **运输在途 · 逐票**：只列未到货的票 + 未发货的渠道。已到货票折叠成一行计数，点开才展开。
   后端按 SKU 给票，一个 SKU 只要还有 1 张没到，同 SKU 十几张早已到货的票都会带出来 ——
   全铺开时 345 行里 173 行是「已到货」，占掉整页 60% 的高度。
6. **按责任人 · 催办视角**（2026-11-06 方案1）：按责任人分块，每块给出
   名下在研 / 超期 / 久悬 / 「最该催」（块内最紧急那个 SKU · 环节 + 已停留）。
   块排序 = 久悬多 → 超期多 → 在研多；**点一行** = 下方在研清单只看这个人。
   日报 xlsx 同口径的「按责任人·催办」sheet 就是这个视图。
   - 与「本月绩效视角」（段级考核：超期段数 / 长期未决 / 本月消化量）分工不同：
     那个给主管看，这个给催办的人逐条勾。
7. **久悬单**（2026-11-06 方案4）：**当前停留段**超期 ≥90 天的 SKU 单列一块。
   - 这批单子催已失效（G538 卡在「素材加工→广告」205 天 / 超期 198 天），要的是**决策**：
     重启评估 / 登记豁免 / 关闭；「建议动作」列给提示（运输域 → 先核对货件是否丢件）。
   - 口径：只算**当前停留段**。历史段曾超 90 天但当前段在跑的**不算**（已经过去了，
     留在「本月已消化超期」对账）。阈值常量 `OVER_STALE = 90`（后端 reporting.py），
     前端 `STALE_DAYS` 同值；30 天（长期未决）是升级提醒，90 天是该拍板。
   - 「建议动作」只出文案，**不改任何状态** —— 关单/豁免仍走人工登记通道。
   - KPI 区第 6 格随之换成「久悬单(≥90天)」；「运输已闭环」的计数本来就在
     「运输已闭环 · 免追踪」区标题上，不再占用 KPI 位。

任意一行都可点开看**事中档案**：型号与状态、多轮提交警示、核心原因（因果链）、段级时间轴。

**段级时间轴的双轨时间列（2026-11-06，与复盘页段级表同口径「照搬」）**：
四列时间戳 = 「实际·起点 / 实际·终点 / audit·起点 / audit·终点」——
实际·起/终 = 纯系统业务日期（表单主字段命中才算，兜底列不算 → 写「缺」）；
audit·起/终 = 纯审批上报时间；两套互不冒充。
「已进行」仍走判定轨（系统 > audit > 动作），数字旁灰字「补」= 该段判定轨里有补位
（兜底列或 audit 补的，时间戳列看不到那个值）。
甘特图与日报 xlsx **不动**（用户口径：保持甘特图不变）；纯轨字段由后端
`_seg_public` 从 `review_sku_segments` 的段行**透传**，不做第二套计算；
旧事中快照里的段行没有这些 key → 前端显示「缺」，重拍快照后自动补齐。

### 2.4 日报 xlsx（按钮「生成今日日报」）

- **落盘**：`<数据根>\<最新批次>\reports\事中日报_YYYYMMDD.xlsx`（同日重跑**覆盖**）。
- **保留**：按 `时效规则配置 → 日报保留天数`（默认 90 天）自动清理。
- **sheet**：固定 **9 张** + 按需最多 2 张（有在研货件时加「货件运输」，有豁免 SKU 时加「豁免备查」），
  固定表无内容时也保留并写占位说明行。顺序：在研SKU状态总表 → 超期明细 → **久悬单** →
  风险预警 → 在研SKU甘特图 → 异常上报清单 → （货件运输）→ 本月已消化超期 →
  本月绩效视角 → **按责任人·催办** → （豁免备查）。

| sheet | 内容 |
| --- | --- |
| 在研SKU状态总表 | 每 SKU 的状态 / 当前停留环节 / 已停留·目标·距超时 / **超期环节**（状态**只认当前停留环节**——当前段超了才标「超期」，只是以前走过的段超了标「预警」；此列仍统计**全部**超期段，前缀「当前·」=现在卡这段、「已过·」=已经走过的那段）/ 预警段数 / 多轮提交 / 核心原因 / 责任人 / **人工登记** |
| 超期明细 | 进行中超期段（终点未完成且 `已进行 > 目标`）。时间列是**纯轨四列**：`实际·起点/实际·终点`（系统业务列，主字段命中才算）＋`audit·起点/audit·终点`（审批上报）；**实际缺失就留空**，绝不拿 audit 值冒充，`说明`列标「判定取 audit 兜底」 |
| 久悬单 | **当前停留段**超期 ≥90 天（`OVER_STALE`）：SKU / 机型 / 停留环节 / 已停留 · 目标 · 超期 / 责任人 / **建议动作**（重启评估 / 登记豁免 / 关闭；运输域先核对货件）。催已失效，是决策清单不是催办清单 |
| 风险预警 | 即将超期（越过 85% 线但未到目标） |
| 在研SKU甘特图 | 每在研 SKU 一块的分段条形（未完成段延伸至今日）。标签列与流程复盘同款 8 列：**A部门 B环节 C起点 D终点** E耗时 F目标 G判定 H执行人，日历轴从 I 列起；未完成段的终点写「进行中」（不伪造完成日期） |
| 异常上报清单 | 当日新超期 + 持续超期累计（拿去上报的那张）。时间列同上纯轨四列；货件超期行只有实际轨（发货日期取 Part5，运输无审批轨） |
| 本月已消化超期 | 本月完成但超期的段（终点落在本月），按超期天数降序。纯轨四列 + `说明`：`判定取 audit 兜底`（实际缺失）/ `终点实际缺失，耗时按兜底列计`（两轨都空但耗时对得上兜底列） |
| 本月绩效视角 | 按责任人：在研超期段数 / 其中长期未决(≥30天) / 当日新超期 / 本月已消化超期段（段级考核） |
| 按责任人·催办 | **SKU 级催办**：责任人块内逐条列 SKU / 状态 / 当前停留 / 已停留 / 距超时 / 建议动作；汇总列只在块首行。块排序 = 久悬多 → 超期多 → 在研多 |
| 货件运输* | 在研 SKU 的真货件（有货件号）：货件号 / 发往地区（渠道仓）/ 运输方式 / 发货·到货日期 / 已运输天数 / 目标天数 / 状态。**全量保留**（2026-11-01 起）：SKU 在研期间每一票都在，到货 ≤5 天标「留观N/5天」、超出标「已归档(到货N天)」——5 天只改状态文案，不删行。**表尾补「未发货渠道」占位行**（2026-11-06）：Part5 已立项但没发货的地区本来无货件号、进不了表，等于看不见；现在逐地区列出——红字`未发货·待登记`=该催/该登记，灰字`未发货·emag不催`走「有发货才标记」口径 |
| 豁免备查* | 被移出追踪的 SKU 及原因（人工登记/换号/末端终止/运输闭环） |

> \* 无内容时不生成该 sheet，不产生空页。
> 「货件运输」sheet 与后台「货件运输」页**同口径全量保留**（2026-11-01 统一）：SKU 一旦进在研
> 就追到它彻底结束，到货 5 天只决定状态文案（留观 → 已归档），两处都不删行。
> 之所以取消截断：留观 5 天虽然能减量，但老票一被剔掉，回头查一张票就得重新跑一遍。
> 首日运行没有上一份快照时，甘特图对比基线缺失属正常——是还没有基线。

**甘特图的开发类型与发布时间（2026-11-01 新增）**：每个 SKU 块的标题行带上
`开发类型 · 官方发布时间`，取自 Part1 产品开发表。

| 标注 | 底色 | 含义 |
|---|---|---|
| 常规开发 / 常规手机壳开发 | 浅蓝 | 按常规节奏排期 |
| ⚡提前开发 | 橙黄 | 窗口比常规短，需要优先盯 |
| IP手机壳开发 | 浅黄 | 手机壳的 IP 款（该品类没有「官方发布时间」列，只显示类型） |
| 开发类型未填 | 灰 | Part1 里没填，需要补数据 —— 不是漏画 |

**日期轴右侧「超期」列（2026-11-01 新增）**：每行末尾给该段的结果 ——
达标写 `✓`，超期写 `超N天`，未完成写 `进行中`，无目标写 `—`。
放在最右侧是为了横向滚到条形末端时也能看到状态，不用滚回左侧标签列；
左侧 G 列判定仍然保留（两处同源，都是 judge）。

**「责任人 / 执行人」是怎么定的（2026-11-01 补回退链）**：一个环节的执行人按下面
顺序取，取到即止；四档都空才显示 `⚠未配置`（那是真的没人可追，不是没查）。

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | **审批动作** | 该环节终点节点上 audit 上报人 / 审批动作执行人（最硬的证据） |
| 2 | **配置责任人** | `seg_rules*.py` 或 `资产文件\责任人配置.xlsx` 里配的默认人 |
| 3 | **审批记录·当前负责人** | 单据此刻停在谁手上（审批中的单据最准） |
| 4 | **审批记录·历史审批人** | 审批链上走过的最后一位**在岗**的人（跳过「已离职」） |
| 5 | 审批记录原文 | 最后一个非（提交申请/通知/抄送/评论）动作的操作人 |

> 为什么要有 3～5：**配置表会变，审批记录不会**。实测手机膜 G599/G600/G601 的
> 「采购→本地仓到货」——该段在规则里责任人本就为空，本地仓到货还没做（节点既无
> 时间也无审批动作），旧逻辑直接渲染「⚠未配置」，但 Part3 单据的「当前负责人」
> 写着夏康富。信息在库里没被取用，日报的「责任人」「超期明细」「绩效视角」三处
> 全错（绩效里还多出一个「(未配置) 3」的桶）。
>
> 顺序上 **配置排在审批记录之前**：配置是管理上指定的责任人，优先尊重；只有配置
> 为空才用审批记录兜底 —— 这样原来有名字的行一个都不会被改（实测 0 处变化），
> 纯粹把原本空着的补上。每条段的来源记在 `execSrc` 字段，排查时能看出这个名字是
> 哪来的。
>
> **运输段**（空运/海运/4 国）没有审批节点，执行人取 Part5「发货」动作的实际操作人
> ——旧逻辑恒为空，4 个在运 SKU 的责任人全是「⚠未配置」。发货是谁做的，这段就催谁。

**「运输·在途」行（2026-11-01 新增）**：甘特图的运输段（空运 / 海运 / 4 国）**只汇总
已到货的票** —— 过滤条件是「有发货日 且 有到货日」。在途票根本不进这些行，于是段一闭合，
看起来就像"运输全到齐了"；括号里的票数也是**已到货票数**，越堵数字越小、反而越像正常。

> 实测 G594：15 票货件到 10 票、**5 票还在路上**（菲律宾 / 印尼 / 泰国 / 加拿大 / 罗马尼亚），
> 甘特图却只写「运输·空运(7票) 09-28→10-21」「运输·海运(3票) 09-28→10-22」，两条都是闭合的。

所以额外出一行「运输·在途(K票)」：

| 列 | 内容 |
|---|---|
| 环节 | `运输·在途(5票)` |
| 起点 | 最早一张**在途票**的发货日 |
| 终点 | 留空 → 条形延伸到今日，终点列写「进行中」（不伪造完成日期） |
| 判定 | `⏳进行中(已N天)`，N = 最早在途票发货至今 |
| 执行人 | Part5 发货操作人（与运输段同口径） |
| 超期列 | `在途5票` |
| 在途明细列（最右） | `已发15·到10·未到5：菲律宾、印尼、泰国、加拿大、罗马尼亚` |

> ⚠️ 这一行**不进状态机**（`displayOnly`）：不产生「超期 / 预警 / 卡点」，也不算
> 绩效。否则它 t1 恒空、t0 又比别的段新，有真实卡点时会把「当前停留」直接抢走 ——
> G594 会从「采购→发货末批」变成「运输·在途(5票)」，责任人、距超时、绩效统计跟着全变。
> 已在 `tests/test_transport_pending_row.py` 用反证钉住这条守卫。
>
> ✅ **例外（2026-11-05）**：流程段**全部走完**、但 `shipClosure=pending`（仍有票未到）
> 时，它**会**成为「当前停留」。原因：此状态下所有段都是「已完成」，旧逻辑退化成
> 「取最晚完成的段」，把停留晒成一个早已到货的「运输·海运(N票)」且已停留为空 ——
> 看图的人以为货还在海上，其实在等的是那批未到货的票（G585-G598 实测 13 个）。
> 现在改为指向「运输·在途(N票)」，已停留 = 最早在途票发货至今，目标天/距超时留空
> （在途票没有承诺时效）。真源 `inflight_service._prefer_in_transit()`，**不变量**：
> 只要有任何一个段在跑/预警/超期，就绝不兜底。
>
> ⚠️ **页面与日报的 emag 口径差（2026-11-06 查明，不是 bug）**：`mute_emag_noship=True`
> 只传给 `generate_daily_report()`，即日报会把 emag「·未发货」占位段剔掉（2026-10-15
> 「有发货才标记」口径），事中页不剔。于是同一天同一个 SKU 会看到两个「当前停留」：
> G599/G600/G601 页面 = `emag罗马尼亚·未发货` 22/23 天，14:10 的日报 = `运输·在途(14票)`
> 6 天。页面清单上方已加口径提示，别再当数据打架查。

**「人工登记」列（2026-10-15 新增）**：跟着日期走的在研备注（如「暂时不弄了」「苹果18duo，23号发售」）。
真源是**生成器之外**的持久文件 `资产文件\事中日报人工登记.xlsx`（子表 `人工登记`，列 `SKU｜备注｜更新日期`）——
因为日报每天整体重新生成、幂等覆盖，**手填在表里的备注下场生成就被冲掉**。改备注只改那个文件，
次次生成自动带到新日报；同一 SKU 多行以最后一行为准。

> ⚠️ 与「豁免备查」里的**人工登记（免催办）**是两件事：那个在
> `资产文件\SKU登记表.xlsx` 的同名子表，作用是把 SKU **移出追踪**。本列只影响展示，
> 不影响任何时效/预警/豁免判定——所以故意分成两个文件，防止误填把 SKU 踢出追踪。

## 三、事后评估页怎么读

只统计**三部门全完成**的 SKU（`可评估 SKU`），口径固定为：

1. **时钟起点** = 品类规则集的 `startNode`（手机膜 = **取数**；手机壳 = **提案**）。
2. **终点** = 最晚**空运**货件到货时间（空运到了就能开卖）。
3. **推迟天数** = `起点 → 最晚空运到货 − 60 天底线`（60 = 空运底线，对齐路线总评级）。
4. **亏损** = `推迟天数 × 评级日均区间 × 单价`；**增益仅在提前完成时才算**。

表格列：SKU / 评级 / 方向（亏损·增益·持平）/ 起点日 / 跨度 / 底线 / 推迟 / 少卖件数 / 损益金额 / 备注。

- **金额是区间估计，不是精确值**（日均来自评级档区间）。
- `备注` 栏会写出口径降级，例如：`无空运货件·按运营路线降级`、`评级未命中`、`缺单价`。
- 按钮「导出三指标 xlsx」导出**时效 / 销量 / 金额**三个 sheet。

## 四、读之前先知道的几件事（口径与坑）

1. **多轮提交**：同一 SKU 同一 Part 有多张单据时，按**最早一轮**取值；若后续还有更新的轮次，标注为「多轮提交·疑似漏报」，**不静默合并**。
2. **反向段**：段耗时为负不是错，常见于「先线下做、后补录」；后台对手机壳把负值标成 `—补录(N天)` 而不报「⚠反向」。
3. **手机壳的目标天 / 评级线目前是"继承手机膜的名义值"**（顶栏品类选择器会亮出「待校准」标记）。因此手机壳的任何「目标 / 超期 / 预警 / 评级」判定**只能当预警参考，不能当既定 KPI**。业务确认数值后才算校准。
4. **已完成的段不进预警区**，所以「预警段数」为 0 不等于这段没风险，只说明当前没有未完成的段。
5. **数据源优先级**：系统业务时间列 > audit 上报 > 审批动作时间。三者在个别 SKU 上会不同，排障时以系统列为准。
6. **部门边界口径（2026-09-24）**：产品部终节点 = **素材交付**（=Part6「产品营销素材加工」，审批记录 audit 时间；该节点无系统业务时间列）；**运营段起点同 = 素材交付**，终点 = max(上架, 广告设置)。产品段目标 23/38 与运营段 7 未变。
7. **「实际」可能是 audit 补录，不是实际发生（2026-11-06 起可对照看）**：SKU 复盘档案里新增**「节点取数核对」表**，把每个节点的 `系统业务日期`（表单里人填的）与 `audit 上报`（钉钉补录时间）并排列出，`实际采用`/`来源` 照旧按「系统 > audit > 动作」取。系统列没填就显示**空**，不会被 audit 冒名顶替。典型现场 G600 的「寄送」：表单根本没有这一列 → 系统空；audit 是 11-05 补录，而「拍摄交付」系统列是 10-22 → 「寄送→拍摄交付」算出 **-14 天**（数据质量信号，不是流程倒挂）。
8. **样机流转合格线 = 签样 → 拍摄交付 < 15 天**（2026-11-06 用户口径）：复盘档案里给出间隔天数和合格判定，**事中日报「在研SKU状态总表」也带这 4 列**（签样(系统) / 拍摄交付(系统) / 样机流转(天) / 流转判定）。这条**只用系统业务日期**计算，任一端缺失就**留空**、不判；15 天 = 签样→寄送(5) + 寄送→拍摄交付(10)，改任一段目标天必须同步复核（`tests/test_review_sample_cycle.py` 有等值断言）。

  判定分三档，别把「流程还没到」当成数据问题：
   | 判定 | 含义 | 该做什么 |
   |---|---|---|
   | `✓合格` | 间隔 < 15 天 | — |
   | `✗超线N天` | 间隔 ≥ 15 天（正好 15 天写 `✗超线`，等于不算合格） | 追产品部 |
   | `未交付` | 签样已做、拍摄交付还没发生（无系统日期） | 等流程 |
   | `待补` | 单据已建、也有 audit 补录，但**系统列空** | 催填表 |
   | `未签样` | 签样都没完成，尚不能起算 | — |

   计算入口唯一：`app/sample_cycle.py`（复盘页与日报共用 `compute()` / `label()`，不各写一份）。**甘特图画法不变** —— 样机流转只做指标，不改时间轴。

9. **双轨对照：判定仍只有一票，audit 只是给判定做体检**（2026-11-06 第二批，口径源 `流程复盘/route_check_sys.py`）。复盘档案的三张表各加一列对照：

   | 位置 | 新增 | 算法 |
   |---|---|---|
   | 段级表 | `audit(天)` + `双轨` 两列 | `audit(天)` = 该段**起点、终点都取**审批上报时间的差值，任一端没有就留 `—`（不拿业务日期或动作顶替）；`双轨` = 换成审批时间后判定是否还成立 |
   | 节点表 | `差异(天)` + `最新审批人` | 差异 = **audit − 系统业务日期**（正数=补录上报晚于单据日期，负数=系统日期填晚了）；最新审批人 = 该节点最晚一条动作的经办人，只展示、不参与取值 |
   | 货件表 | 发货/到货格下方灰字 | 每件货件用它**自己那张** Part5/Part8 单据的审批上报，不拿 SKU 级「最早一轮」顶替 |

   `双轨` 的四档含义：
   | 显示 | 含义 | 怎么用 |
   |---|---|---|
   | `一致` | 系统轨与 audit 轨结论相同（都 ✓ 或都 ✗） | 这条超时是真的 |
   | `仅系统轨超线`（橙） | 系统日期算超了，换审批时间算没超 | 超时可能来自**填报日期**，先回查表单 |
   | `audit 轨更差`（橙） | 表单日期过线内，审批时间反而超了 | 表单日期比实际"好看"，以审批侧为准复核 |
   | `—` | 任一端缺 audit / 该段不设目标 / 系统轨本身不是 ✓✗ | 无可比性，不评 |

   🔴 铁律：**audit 轨永不参与判定**。判定只由系统轨给一票（`_seg_judge`），双轨只用来分清「真慢」和「日期填错」—— 否则又会变成同一件事两个结论（预警数打架、管线时刻假值都是这么来的）。口径收口 `app/dual_track.py`，判定函数由 review 注入、禁止复刻；`tests/test_dual_track.py` 拿离线件产出 xlsx 逐行对账。

   **段级时间戳纯轨拆列**（2026-11-06 第三批，用户口径「实际就是实际，audit 就是 audit」）：段级表把「起点 → 终点」一格拆成四列 —— `实际·起点` / `实际·终点` 只装**真系统业务日期**（候选链**主字段**命中才算，兜底列不算；如提案候选 =（提案日期，创建时间），G600 那批表单没有提案日期列 → 实际·起点写「缺」，**不用创建时间冒充**）；`audit·起点` / `audit·终点` 只装审批上报。两套互不冒充，缺写「缺」（斜体灰）。`实际(天)` 与判定**留判定轨**（系统>audit>动作），数字旁灰字「补」= 该段判定轨有补位（时间戳列看不到它）。真源 `extract_node_times.sys_real`（`_primary_sys_field` 判主字段），缓存键 v3。

   ⚠️ 货件层的 audit 只取审批记录，**没有**离线件那层「Part8 Sheet2 审批时间」兜底（后台不读导出文件的第二个 sheet）→ 覆盖率略低，缺就留空。

## 五、离线对照（同一口径的另一条腿）

仓库 `流程复盘/route_check_sys.py` 是**系统口径**的离线实现，与后台同源同义：

- 产出 `output/route_路线复盘_系统口径.xlsx`，第 2 张 sheet **「事中盯办」** = 事中页的离线版本（每 SKU 只列**当前卡点段** + 状态 + 催办动作，按卡住天数降序，可直接照着打电话）；
- 默认只列「当前卡点段」；`--inflight-all-segs` 放开全部段，`--no-inflight` 关闭；
- 核对脚本 `流程复盘/check_inflight.py`（读产物做列/枚举/自洽/快照幂等/零波动核对）。

> 后台用于**日常盯办与上报**；离线脚本用于**留档、对比与排障**。两边报的是同一套数。

## 六、常见问题

**Q：页面显示「无在研 SKU」？**
A：说明当前品类的单据都已完成/终止。先确认顶栏**品类**与**批次**选对了。

**Q：KPI 与昨天不一样，是不是数据坏了？**
A：先看是否跨天（「已进行天数」本身按天增长，跨天变化是正常的），再看上游同步是否成功（`backend/state/auto_pipeline.log`）。

**Q：改了规则没生效？**
A：规则保存后会说「已按新规则重新计算」。若计划任务时间类需求，**规则页改不了**——那属于 Windows 计划任务，见 §一。
