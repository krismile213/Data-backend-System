## 一、先看懂业务：我们到底在做什么

新人最容易犯的错，是把这 9 个 Part 当成 9 张孤立的审批单去填。实际上它是**同一款新品从立项到多渠道上架的完整生命周期**：一款手机膜从确认开发，到样品入本地仓、下单采购、发往 15 个海外渠道仓，同时完成素材拍摄、页面首次上架、最终上架与广告投放，最后到渠道仓到货、促销邀评启动。

### 1.1 产品与市场

- **品类**：手机膜（**钢化膜**为主，少量 **水凝膜**），单批次 60~80 款新品
- **覆盖渠道（15 个）**：

| 渠道组     | 站点                               |
| ------- | -------------------------------- |
| 亚马逊（10） | 美国、英国、加拿大、墨西哥、澳洲、阿联酋、沙特、印度、日本、欧洲 |
| 美客多（1）  | 墨西哥                              |
| 东南亚（2）  | 菲律宾、印尼                           |
| 欧洲其他（2） | emag 罗马尼亚                        |

- **目标区域分组**：`欧洲以及全球` / `印度东南亚` / `日本专供`  
  —— 分组决定该 SKU 要上架哪些站点、备货往哪些仓发，填单前先确认。

### 1.2 两类开发路径（**决定考核标准，必须先分清**）

| 开发类型     | 判定口径                      | 业务特征                 | 考核差异                             |
| -------- | ------------------------- | -------------------- | -------------------------------- |
| **提前开发** | Part1「官方发布时间」**晚于**提交申请时间 | 新机未发布就提前跟，节奏受官方发布日牵引 | Part1 取数**不考核**；Part6 素材 13~15 天 |
| **常规开发** | 其余                        | 官方已发布，按正常节奏推进        | Part1 考核 1 天；Part6 素材 3 天        |

> 判定由系统自动完成，可在「复盘总览」页核对。**接手任务时第一件事就是确认这个 SKU 属于哪一类**，  
> 否则会用错时效标准、误判"超时"。

### 1.3 流程全景与三个部门终节点

```
Part1 产品开发 ──→ Part2 新品首单下单 ──→ Part3 新品本地仓到货 ★全流程关键闸门
                                              │
                                              ├──→ Part5 新品渠道仓发货 ──┐
                                              │        （逐货件号发往各渠道仓）
                                              └──→ Part6 新品素材跟进 ────┘ ★产品部终节点
                                                        （寄拍→收素材→加工）

Part4 新品站点首次上架（各站点先上"占位"）
                    │
                    └──→ Part7 最终上架 + 广告上架 ★运营部终节点
                                    │
Part8 新品渠道仓到货 ★后勤部终节点 ──┴──→ 促销开始 / 邀评开始 / 广告检查
                                    │
                              Part9 新品环节检查（QA 抽查）
```

**三个终节点是全流程的考核锚点**：

| 部门  | 环节    | 终节点动作     | 完成标志            |
| --- | ----- | --------- | --------------- |
| 产品部 | Part6 | 产品营销素材加工 | **素材交付**（=Part6「产品营销素材加工」，审批记录 audit 时间；该节点无系统业务时间列） |
| 运营部 | Part7 | 上架 + 广告设置 | **最终上架与广告上架完成** |
| 后勤部 | Part8 | 到货通知      | **渠道仓到货**       |

只有**三个终节点全部完成**的单据才算"有效复盘对象"，未闭环的会在系统里标为停滞。

### 1.4 为什么要理解环节之间的依赖（而不是各干各的）

这是新人最需要建立的认知，也是过去最容易出问题的地方：

- **Part3 卡住 → 后面全卡**：签样没完成，Part2 的采购下单无从谈起，整条线停摆。
- **Part5（渠道仓发货）停滞会拖住 Part6（素材）**：素材拍摄需要实物样机，样机随首批货件发出。  
  但**素材其实可以与发货解耦提前启动**（签样完成后即可寄拍）——系统「联动提醒」页就是专门  
  盯这件事的，发货停滞 ≥ 阈值而素材未启动的 SKU 会被单独列出来催办。
- **Part4（首次上架）与 Part7（最终上架）是两件事**：Part4 是各站点先上架占位、防止被别人抢 listing；  
  Part7 才是素材齐备后的正式上架 + 广告投放。**素材没完成就谈不上 Part7**，而素材完成又依赖 Part6。
- **Part8 到货 ≠ 结束**：到货后 1 天内要完成手机上架确认、2 天内启动促销，否则错过新品流量窗口。

## 三、逐环节 SOP

> 每节结构：**业务目标 → 触发 → 关键动作链 → 必填字段 → 时效 → 完成标志 → 常见卡点**  
> 标 ⏱ 的动作会被系统计入该环节耗时统计。

### Part1 产品开发

- **业务目标**：确认这个新机型号值得做，拿到真机数据，完成立项并通知各部门。
- **触发**：选品评审通过后发起。
- **关键动作链**：  
  `提交申请` → ⏱`提案确认` → ⏱`取得手机数据` → ⏱`产品信息补充` → ⏱`通知_手机数据已取得`  
  （`通知_产品立项`、`通知_东南亚运营` 属提案确认后的并发抄送，**不单独计时**）
- **必填字段**：开发类型、目标区域、手机膜类型、新机型号、参考SKU、官方发布时间、  
  亚马逊上架或预计上架时间、手机数据取得日期、官方发布信息渠道
- **时效**：常规开发 **1 天**（提案确认/取数/补信息一天内完成）；提前开发**不考核**此项
- **完成标志**：`通知_手机数据已取得` 动作完成
- **常见卡点**：
  - 提前开发的官方发布时间填错 → 直接被误判成常规开发，后续所有时效标准全部套错；
  - 「目标区域」没填准 → Part4/Part5 的站点范围跟着错，属于源头性错误。

### Part2 新品首单下单

- **业务目标**：收集各站点备货需求与特殊需求数量，完成全套样品测试后下达首单采购。
- **触发**：Part1 立项完成（拿到手机数据）后发起。
- **关键动作链**：  
  `提交申请` → ⏱`站点需求收集` → ⏱`特殊需求数量收集` → ⏱`全套样品测试完成` → ⏱`采购下单`  
  （两条"通知全体站点负责人…备货数量"为收集动作的并发通知，不单独计时）
- **必填字段**：**各站点备货数量**（东南亚印尼/泰国/菲律宾、亚马逊美英德法意西荷比爱波瑞捷土日印澳加墨阿、emag罗马尼亚、美客多墨西哥）、  
  是否真机测试、特殊需求数量、供应商售后承诺书（**非真机测试时必填**）、  
  全套样品测试完成时间、首单下单时间
- **时效**：**1 天**（签样后即下单，临近下班跨工作日属正常）
- **完成标志**：`采购下单` 动作完成
- **常见卡点**：
  - 站点备货数量与「目标区域」不匹配 → 发错仓，后续 Part5/Part8 全乱；
  - **非真机测试却漏填供应商售后承诺书** → 审批被打回重走，白白吃掉 1 天时效。

### Part3 新品本地仓到货 ★全流程关键闸门

- **业务目标**：新品抵达本地仓，仓管检查到货并通知跨境店负责人。
- **触发**：供应商发货后。
- **关键动作链**：`提交申请` → ⏱`本地仓到货检查`
- **必填字段**：本地仓到货时间、手机数据取得时间
- **时效**：**320 小时（约 13.3 天）** —— 提前开发与常规开发同标准
- **完成标志**：`本地仓到货检查` 完成 = **签样完成** = 全流程关键闸门（产品部终节点已改为 Part6 素材交付）
- **常见卡点**：
  - 这是**全流程的关键闸门**（产品部终节点见 Part6 素材交付）：签样不完成，Part2 的采购下单无法推进；
  - 该动作原由一位已离职同事承担 249 次，是当前**交接风险最高**的单点。

### Part4 新品站点首次上架

- **业务目标**：新品在各站点完成**首次上架占位**，防止 listing 被抢。
- **触发**：产品资料齐备后（通常与 Part5 发货并行）。
- **关键动作链**：`提交申请` → ⏱`新品首次上架` → ⏱`新品上架完成`  
  （`抄送美客多同时进行上架` 为并发节点）
- **必填字段**：**各区域上架完成图片**（中东/北美/印度/日本/欧洲/澳洲/英国）、  
  全站点首次上架完成日期、是否完成全部站点首次上架
- **时效**：**2 天**（含节假日放宽至 7 天）
- **完成标志**：`新品上架完成` 动作完成
- **常见卡点**：
  - 「是否完成全部站点首次上架」没勾是常见的"假完成"，会让后续 Part7 无法正常推进；
  - 上架完成图片按区域分别上传，**漏传某个区域等于该区域没上架**。

### Part5 新品渠道仓发货

- **业务目标**：本地仓向各渠道仓（FBA 等）发货，**逐货件号记录**。
- **触发**：Part3 签样完成、库存就绪后。
- **关键动作链**：`提交申请` → ⏱`发货`  
  （`通知广告组上架广告` 为发货后的并发通知，部分单据未触发视为流程省略）
- **必填字段**：**货件号**、发货数量、发货日期、**发往渠道仓库**
- **时效**：**840 小时（35 天）** —— 与常规开发同标准
- **完成标志**：`发货` 动作完成（**一票一单**，多个货件号 = 多张审批单）
- **常见卡点**：
  - 这是**单据量最大的环节之一**（单个批次 2752 条提交、3608 次发货动作），  
    货件号填错或漏填会直接导致 Part8 到货无法匹配；
  - **发货停滞会连锁卡住 Part6 素材**（样机随货发出），但素材实际可提前启动 ——  
    见「联动提醒」页的 R1 清单。

### Part6 新品素材跟进 ★产品部终节点

- **业务目标**：寄送样机给拍摄团队、接收素材、加工营销素材并通知完成。
- **触发**：签样完成后即可启动（**不必等发货**）。
- **关键动作链**：  
  `提交申请` → ⏱`寄送拍摄团队` → ⏱`素材接收` → ⏱`产品营销素材加工` → ⏱`新品营销素材完成通知`
- **必填字段**：是否决定拍摄、素材参考SKU/型号、寄送拍摄团队日期、  
  拍摄团队素材交付日期、最终素材上传路径、手机数据取得时间
- **时效**：
  - **常规开发 3 天**（3 天内完成一个 SKU 的素材）
  - **提前开发 13 天确认 / 15 天建议**（寄拍接收 10 天 + 收到素材后 3 个工作日/SKU）
- **完成标志**：`新品营销素材完成通知` 动作完成
- **常见卡点**：
  - **最常见的误解**：以为要等 Part5 发货才能寄拍 —— 这是"页面 coming soon"的根因。  
    签样完成就应寄出，素材与发货解耦；
  - 「是否决定拍摄」选否的单据，后续素材动作会被跳过，需确认是业务决策而非漏填。

### Part7 新品站点最终上架和广告上架 ★运营部终节点

- **业务目标**：素材齐备后，新品**最终上架**到各站点并完成**广告投放设置**。
- **触发**：Part6 素材完成 + Part4 首次上架完成后。
- **关键动作链**：`提交申请` → ⏱`上架` → ⏱`广告设置`
- **必填字段**：是否完成最终上架、最终上架完成时间、是否完成广告上架、广告上架完成时间、  
  **橱窗图与视频上传路径**
- **时效**：**7 个工作日**（最终上架 + 广告，两动作合计）
- **完成标志**：`上架` + `广告设置` 都完成 = **运营部终节点达成**
- **常见卡点**：
  - 素材未完成就发起 Part7 → 最终上架做了也白做，页面仍是空壳；
  - 「橱窗图与视频上传路径」是素材落地的最后一步，漏填会导致素材没真正应用到 listing。

### Part8 新品渠道仓到货 ★后勤部终节点

- **业务目标**：渠道仓到货确认，随后手机上架、促销/邀评/广告检查同步启动。
- **触发**：Part5 发货后，货件抵达渠道仓。
- **关键动作链**：  
  `提交申请` → ⏱`到货通知` → ⏱`手机上架确认` → ⏱`新品促销开始`  
  （`新品邀评开始`、`检查广告是否设置完成` 与促销开始同刻，取其一计时）
- **必填字段**：**货件号**、到货数量、**到货渠道仓**、渠道仓到货时间、手机上架日期
- **时效**：**15 天**（口径：确认 ≤1 天 + 促销 ≤2 天；到货运输本身 12~35 天，取代表值）
- **完成标志**：`到货通知` 完成 = **后勤部终节点达成**（渠道仓到货）
- **常见卡点**：
  - 到货后**超过 1 天才做手机上架确认、超过 2 天才启动促销** → 直接错过新品流量窗口，  
    这是时效口径里唯一按"自然日"卡得很紧的两处；
  - 货件号与 Part5 对不上 → 到货无法关联，两边的统计都会失真。

### Part9 新品环节检查

- **业务目标**：QA 抽查前序各环节的完成情况。
- **触发**：**Part7 完成后 1 天内**发起。
- **关键动作链**：`提交申请` → ⏱`环节检查`
- **必填字段**：检查时间、检查环节、未完成站点、完成情况、完成情况截图
- **时效**：**1 天**（最终环节，无下游依赖，不计入贡献度）
- **完成标志**：`环节检查` 动作完成
- **常见卡点**：该环节多为流程进行中状态，**「未完成站点」必须如实填写** ——  
  这是发现前面环节漏做的最后一道防线。

| Part5 渠道仓发货   | 840h（35 天）      | 840h（35 天）    | ✅         |
| Part6 素材跟进    | 13 天确认 / 15 天建议 | 3 天           | ✅         |
| Part7 最终上架+广告 | 7 个工作日          | 7 个工作日        | ✅         |
| Part8 渠道仓到货   | 15 天            | 15 天          | ✅         |
| Part9 环节检查    | 1 天             | 1 天           | 不计贡献      |

**路线达标口径**（用于整体评级，见「路线达标」页）：

| 路线   | 计算方式             | 优     | 良          | 差     |
| ---- | ---------------- | ----- | ---------- | ----- |
| 运营路线 | 取数 → max(上架, 广告) | ≤52 天 | ≤60 天      | >60 天 |
| 空运路线 | 取数 → 最晚空运货件到货    | ≤49 天 | ≤60 天      | >60 天 |
| 海运路线 | 取数 → 最晚海运货件到货    | ≤69 天 | >69 天（不设良） | —     |

> **重点复盘口径**：两条路线均 ≤60 天、且后勤 < 运营 → 判定为「**运营环节拖后腿**」。

## 五、异常口径：系统是怎么判定问题的

新人不需要背，但**要能看懂并在被问到时解释**：

| 异常类型          | 判定口径                                     |
| ------------- | ---------------------------------------- |
| 长期未完成（停滞）     | 审批中，且距基准时间 > `max(3 天, 该环节已结束单据全流程 P90)` |
| 环节耗时超长        | 分段耗时 > `max(7 天, Q3 + 1.5×IQR)`          |
| 分段耗时异常小（疑似补录） | 耗时 < 0.1h 且该环节中位数 ≥ 1h                   |
| 流程回退/重做       | 关键动作多次出现                                 |
| 节点时间乱序        | 审批记录里时间倒挂                                |
| 已结束但流程未到终节点   | 审批状态已完成，但终节点动作缺失                         |
| 业务时间列缺失       | 已结束单据的关键业务日期为空                           |
| 流程中途换号        | 旧号停用、新号承接（人工登记在独立「SKU登记表.xlsx」的「SKU换号」子表）；旧号**必然**停在中途，**不算异常** |
| 业务上已不需走完流程    | 业务决定不再走完（渠道取消 / 并入其它型号 / 末端环节实际不执行），人工登记在独立「SKU登记表.xlsx」的「人工登记」子表；**不算异常**、不催办 |

> 判定阈值可在系统「规则配置」页调整，改完复盘与预警立即重算。
>
> **三条「不催办」通道是三回事**，都不催办、只单列备查：
> **作废单**是系统从**数据推断**出来的（末尾单据全终止）；
> **换号**是业务登记的事实（旧号停用、**有新号承接**）；
> **人工登记**也是业务登记，但**没有承接号**（业务上就是不再走完流程了，多见于货已在售、渠道取消）。
> 命中次序：**人工登记 > 换号 > 末端终止**（人工决策最可信）。

## 六、新人上手 30 天路径

**第 1 天 —— 只做三件事**

1. 打开系统，把「时效看板」「复盘总览」各看一遍，建立整体印象；
2. 打开本手册第一节，画一遍流程链，能说出三个部门终节点分别是什么；
3. 在「明细查询」里随便挑一个已完成的 SKU，**按 Part1→Part9 把它的审批记录翻一遍**，  
   看清楚同一款产品是怎么走完全程的。

**第 1 周 —— 跟单为主**

- 跟随带教人完成 2~3 个 SKU 的完整流转，**每个动作都亲手提交一次**；
- 重点熟悉 Part2 的站点备货数量填写（最容易填错的地方）；
- 每天看一次「加急预警」页，理解 P0/P1/P2 的分级含义；
- 知道页面下方的「**已终止 · 不催办**」是**作废单**（撤回 / 填错重开 / 型号取消），
  **不需要催办**：若结论写「已由 XXX 重开（承接单已闭环）」说明已经重开并走完，
  写「无承接单，请确认」才需要找业务核实是不是漏了重开。
- 知道「**已换号 · 不催办**」是**流程中途换了编码**（旧号停用、新号承接，常见于机型变更）：
  旧号停在中途是正常的，**不需要催办**。可以在复盘总览搜旧号看 Chip「换号 → 新号」，
  或搜新号看「承接 旧号」；流程甘特图里那条**灰色竖虚线**就是换号衔接点。
  如果发现某个 SKU 其实换号了但系统还在催办，**找业务确认后登记到独立「SKU登记表.xlsx」的「SKU换号」子表**
  （旧SKU / 新SKU / 换号说明 / 生效日期），重导登记表即生效。
- 知道「**已豁免 · 不催办**」是**业务上已不需走完流程**（货早在售、渠道取消、并入其它型号，
  **没有新号承接**）：单据挂在半路是历史遗留，**不需要催办**。复盘里它的部门结论会写「人工豁免·不催办」，
  甘特图上是**灰色点线**。⚠️ 这种「不再走完」是**人工决策**，系统推不出来 ——
  发现某 SKU 该豁免却还在催办，**找业务确认后登记到独立「SKU登记表.xlsx」的「人工登记」子表**
  （SKU / 说明 / 登记日期），并在说明里写清依据（如「Part8 两张单据为历史悬挂、不计入时效」），重导登记表即生效。

**第 1 个月 —— 独立负责**

- 独立负责若干 SKU，带教人抽查；
- 学会看「异常排查」页，能解释自己负责的单据为什么被标异常；
- 掌握「场景诊断」「联动提醒」两个页面 —— 从"做事"升级到"提前发现问题"。

**转正自查**

- [ ] 能说清提前开发与常规开发的差别，以及为什么 Part1 对提前开发不考核
- [ ] 能解释为什么 Part5 发货停滞会卡住 Part6 素材，以及正确的做法是什么
- [ ] 能说清三个部门终节点分别对应哪个动作
- [ ] 独立处理过一次审批被打回的情况，知道问题出在哪
- [ ] 知道遇到异常时去哪个页面查、问谁
